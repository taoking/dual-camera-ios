本文仅记录主要开发、构建、测试、发布和真机安装结果。个人 Team ID、证书、Apple ID 和描述文件内容不会写入仓库。

## 2026-07-27：第六阶段非阻断保存与录制反馈

### 实现范围

- 照片合成完成后不再停止 `AVCaptureMultiCamSession` 或自动打开全屏结果页；最近照片以左下角缩略图保留，并立即进入后台自动保存。
- 视频停止后立即切回照片模式并恢复取景；`finishWriting` 成功后再发布最近视频并自动保存，不因 PhotoKit 写入暂停预览。
- 新增 `MediaSaveCoordinator`：照片 UUID／视频 URL 作为任务 ID，同一媒体只允许一个活跃保存任务；旧媒体完成回调只做必要的资源收尾，不会覆盖最新媒体徽标、提示或触感。
- 新媒体替换仍在保存的旧视频时延迟删除 `.mov`，避免 PhotoKit 读取期间文件被提前移除。
- 录像成功开始时分配 Session 队列单调序号；用户在 `finishWriting` 期间拍的更新照片不会被较晚返回的旧视频覆盖。
- 被替换的视频保存失败时保留唯一 `.mov`，在替换当下或下次 active 静默重试；只在成功后删除。
- 新增准备录制、录制中、视频处理中状态。录制时长使用 `systemUptime` 和 common RunLoop 计时，显示 `MM:SS`，超过一小时显示 `HH:MM:SS`。
- 保存失败时保留最近媒体并提供重试；用户主动点击缩略图才进入照片／视频查看页，查看状态不再参与 Session 生命周期启动判定。
- UI 测试的顶部 SwiftUI `Menu` 增加 `isHittable` 检查和中心坐标点击回退，用于兼容 GitHub iOS 18.5 Runner 的 AX 点击问题。

### 发布前复审修复与最终验收状态

提交前又进行了两轮独立只读复审，修复了以下边界：

- 保存任务持续强持有到 PhotoKit 真实回调，同一视频在恢复索引完成更新前仍计入 active，关闭容量检查的短暂漏计窗口。
- 可操作提示使用唯一提示 ID、恢复优先级和媒体任务 ID；媒体成功只清除同一任务的失败入口，旧按钮不会消费后来提示。查看页重试与 Session 重试都会覆盖全部待恢复媒体。
- 最近照片保存当次 `PhotoSaveMode` 快照；拍摄后修改设置不会改变查看页说明或该照片的重试内容。
- writer 输出 URL 先登记为持久化 `inFlight`，只有 `finishWriting` 成功才原子提升为 `ready` 并交给 PhotoKit；启动、取消或封口失败会清理对应索引。
- 冷启动只处理 `MediaRecoveryStore` 初始化时载入的上一进程 in-flight 快照。包含顶层 `ftyp`／`mdat`／`moov` 的封口 MOV 提升为 ready，缺失文件清索引，未封口或非法文件清理；本进程后来登记的 writer 不受重复恢复影响。
- 自有 `DualCamera-*.mov` 孤儿缓存只在每个进程首次启动时扫描，要求至少 5 分钟，并在恢复索引锁内二次核验后删除，避免并发 Controller 或正在保存的文件被误删。
