# 开发签名续期与真机更新手册

本手册用于把当前工程的 Debug 开发包更新到自己的 iPhone。它适用于本项目默认不保存个人签名信息的设计：每台开发电脑在本地使用自己的 Apple 账号、Team、Bundle ID 和设备标识构建，**不要把这些值提交到 GitHub**。

> 使用免费的个人开发团队时，设备上的开发签名应用通常只可使用约 7 天。到期后不需要删除应用或重新配置功能；重新构建并覆盖安装，再在需要时信任开发者即可。

## 一次性准备

### 1. 安装与登录 Xcode

1. 从 App Store 安装完整 Xcode，并首次启动完成组件安装和许可确认。
2. 打开 **Xcode → Settings → Accounts**，登录用于开发的 Apple ID。
3. 打开 `DualCamera.xcodeproj`，在左侧 Project navigator 点击蓝色项目图标 **DualCamera**，再在中间面板的 **TARGETS** 列表选择 **DualCamera**，进入 **Signing & Capabilities**。
4. 勾选 **Automatically manage signing**，在 **Team** 选择自己的团队。
5. 将 Bundle Identifier 改为自己唯一的标识，例如 `com.example.dualcamera`。

工程仓库中的默认 Bundle Identifier 是通用占位值；个人 Team、证书、描述文件和真实 Bundle Identifier 都只应保留在本机。

如同时安装稳定版和 Xcode Beta，二者的 Accounts 需要分别核对；Beta 未登录时，`xcodebuild -allowProvisioningUpdates` 会报 `No Accounts`。当设备系统版本高于稳定版 SDK 时，使用与设备匹配的 Xcode（例如 iOS 27 使用 Xcode 27），并只在当前命令前临时指定：

```sh
export DEVELOPER_DIR='/路径/Xcode-beta.app/Contents/Developer'
```

用完关闭终端或执行 `unset DEVELOPER_DIR`，无需修改系统全局 Xcode 选择。

### 2. 准备 iPhone

1. 用数据线连接 iPhone，保持解锁，并在提示时选择“信任此电脑”。
2. 打开 **设置 → 隐私与安全性 → 开发者模式**，开启后按系统要求重启并确认。iOS 版本不同，菜单名称可能略有差异。
3. 在 Xcode 顶部设备菜单中确认该 iPhone 可选；也可运行以下命令确认：

```sh
xcrun devicectl list devices
```

真机需要支持 `AVCaptureMultiCamSession`。模拟器只能运行 Fake Camera 自动测试，不能验证真实前后摄。

## 每次更新：一条命令（推荐）

个人开发签名约 7 天到期，到期后应用图标点不开。此时**不需要**删除应用、不需要重新配置，
只要连上手机跑一次：

```sh
./scripts/install-to-device.sh
```

脚本会自动完成：选择带合适 iOS SDK 的 Xcode、找到已连接的真机、读取签名配置、
构建签名、覆盖安装、启动。全程约一分钟。

### 使用前提

- iPhone 用数据线连接电脑，**保持解锁**
- 首次连接时在手机上选择「信任此电脑」
- 「设置 → 隐私与安全性 → 开发者模式」已开启
- Xcode 已登录 Apple ID（**Xcode → Settings → Accounts**）

### 关于个人信息

Team ID 与 Bundle Identifier 首次运行时自动探测，保存在 `scripts/.device-config`。
该文件已在 `.gitignore` 中，不会进仓库。删除它可重新探测。

需要覆盖时用环境变量：

```sh
DUAL_CAMERA_TEAM=<你的 Team ID> \
DUAL_CAMERA_BUNDLE_ID=<你的 Bundle Identifier> \
./scripts/install-to-device.sh
```

### 可能遇到的两种情况

**手机锁屏**：安装已经成功，只是自动启动被系统拒绝。解锁后直接在桌面点开
「双摄相机」即可，不必重跑脚本。

**提示需要信任开发者**：换了签名证书后第一次启动会遇到。按脚本给出的指引，
在手机上打开 **设置 → 通用 → VPN 与设备管理**，在「开发者 App」下选择你的
Apple Development 开发者并点「信任」，然后在桌面点开应用。

### 换成正式开发者账号之后

付费开发者账号的签名有效期是一年，不再需要每 7 天重装。届时只要在
**Xcode → Settings → Accounts** 登录新账号，删除 `scripts/.device-config`
让脚本重新探测 Team ID，其余步骤完全不变。

## 每次更新：推荐的 Xcode 图形界面方式

这是最适合日常续期的方式。

1. 拉取或切换到需要安装的源码，打开 `DualCamera.xcodeproj`。
2. 确认 Scheme 为 **DualCamera**，运行目标为已连接的 iPhone。
3. 在 **Signing & Capabilities** 确认 Team 和 Bundle Identifier 仍是自己的配置，且自动签名开启。
4. 按 `⌘R`（Product → Run）。Xcode 会构建、签名并覆盖安装旧版本。
5. 首次使用或系统提示时，在手机上允许相机、麦克风和“添加照片”权限。
6. 打开应用，确认前后取景均可见；拍一张照片和录一段短视频，确认界面没有停止取景。

若提示描述文件缺失，先保持手机已连接、解锁，再到 Signing & Capabilities 选择正确 Team，等待 Xcode 自动生成描述文件后重新 Run。

## 每次更新：命令行方式

命令行适合需要保留明确构建记录或不打开 Xcode 时使用。以下命令在仓库根目录执行。

### 1. 设置本机临时变量

不要把真实值写入脚本、文档或 Git 配置。每次在当前终端临时设置即可：

```sh
export DUAL_CAMERA_TEAM='<你的 Team ID>'
export DUAL_CAMERA_BUNDLE_ID='<你的唯一 Bundle Identifier>'
export DUAL_CAMERA_DEVICE_ID='<xcrun devicectl list devices 显示的 Identifier>'
export DUAL_CAMERA_UDID='<设备详情中的 UDID>'
export DUAL_CAMERA_BUILD_DIR='/tmp/dualcamera-device-build'
```

设备详情（含 UDID、开发者模式状态）可用下列命令检查：

```sh
xcrun devicectl device info details --device "$DUAL_CAMERA_DEVICE_ID"
```

### 2. 推荐的本地校验

简单续期至少应通过无签名 iPhoneOS 构建；发布或重要改动时再跑完整自动测试。

```sh
plutil -lint DualCamera/Info.plist
git diff --check

xcodebuild test -project DualCamera.xcodeproj -scheme DualCamera \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -only-testing:DualCameraTests \
  CODE_SIGNING_ALLOWED=NO

xcodebuild test -project DualCamera.xcodeproj -scheme DualCamera \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -only-testing:DualCameraUITests \
  CODE_SIGNING_ALLOWED=NO

xcodebuild -project DualCamera.xcodeproj -scheme DualCamera \
  -sdk iphoneos -configuration Debug \
  -derivedDataPath "$DUAL_CAMERA_BUILD_DIR-unsigned" \
  CODE_SIGNING_ALLOWED=NO build
```

如果模拟器名称或系统版本不同，先执行 `xcrun simctl list devices available`，替换为一台可用 iPhone 模拟器。只有 `project.yml` 改动时才需要执行 `xcodegen generate`；普通源码更新无需重新生成工程。

### 3. 开发签名构建

`-allowProvisioningUpdates` 允许已登录的 Xcode 在本机缺少描述文件时创建或下载匹配的开发描述文件。它要求网络可用、正确的 Apple 开发权限，以及已连接的目标设备。

```sh
xcodebuild -project DualCamera.xcodeproj -scheme DualCamera \
  -configuration Debug \
  -destination "platform=iOS,id=$DUAL_CAMERA_UDID" \
  -derivedDataPath "$DUAL_CAMERA_BUILD_DIR" \
  -allowProvisioningUpdates \
  DEVELOPMENT_TEAM="$DUAL_CAMERA_TEAM" \
  PRODUCT_BUNDLE_IDENTIFIER="$DUAL_CAMERA_BUNDLE_ID" \
  CODE_SIGN_STYLE=Automatic \
  'CODE_SIGN_IDENTITY=Apple Development' \
  build
```

验证签名并覆盖安装：

```sh
export DUAL_CAMERA_APP="$DUAL_CAMERA_BUILD_DIR/Build/Products/Debug-iphoneos/双摄相机.app"

codesign --verify --deep --strict --verbose=4 "$DUAL_CAMERA_APP"
xcrun devicectl device install app --device "$DUAL_CAMERA_DEVICE_ID" "$DUAL_CAMERA_APP"
xcrun devicectl device process launch --device "$DUAL_CAMERA_DEVICE_ID" \
  --terminate-existing "$DUAL_CAMERA_BUNDLE_ID"
```

最后一条命令成功时会显示已启动。也可检查进程：

```sh
xcrun devicectl device info processes --device "$DUAL_CAMERA_DEVICE_ID" | \
  rg '双摄相机|dualcamera'
```

## 首次安装或重新签名后的“信任开发者”

如果安装成功、但启动报“签名无效、entitlement 不足，或描述文件尚未被显式信任”，这是 iPhone 的安全保护，命令行不能绕过。请在手机解锁状态执行：

1. 打开 **设置 → 通用 → VPN 与设备管理**。
2. 在 **开发者 App** 下选择当前的 Apple Development 开发者。
3. 点击 **信任**，并在系统二次确认时再次选择信任。
4. 回到电脑重新执行上一节的启动命令，或直接在手机桌面打开“**双摄相机**”。

如果“开发者 App”没有出现，先确认开发者模式已启用、手机仍解锁并已信任电脑；然后重新执行签名构建和安装步骤。不要通过删除描述文件或任意更换 Team 来尝试绕过系统信任。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `No Account for Team` | Xcode 未登录该 Team 对应的 Apple ID，或 Team 选错。到 Xcode → Settings → Accounts 重新登录／选择团队。 |
| `No profiles ... were found` | 本机没有匹配描述文件。连接并解锁手机，确认唯一 Bundle ID，然后使用 `-allowProvisioningUpdates` 或在 Xcode 开启自动签名。 |
| 设备显示“iOS X 不可用／未安装” | 当前命令行 Xcode 的 SDK 低于手机系统版本。安装或使用匹配的 Xcode；若已安装 Beta，以 `DEVELOPER_DIR` 临时指向它。不要用 `-downloadPlatform iOS` 仅为真机问题下载完整模拟器运行时。 |
| 安装成功但无法启动 | 先检查开发者模式，再按上一节在“VPN 与设备管理”信任开发者。 |
| 设备不在 `devicectl list devices` | 更换可传输数据的数据线／接口，解锁手机并信任电脑；必要时重开 Xcode 和手机。 |
| 7 天后图标无法打开 | 开发签名到期。重复“每次更新”中的构建、安装和启动步骤即可，通常不需要删除旧应用。 |
| 相机显示不支持 | 该设备或当前系统组合不支持并发前后摄；本应用不会降级为伪双摄。 |
| 有画面但无法保存 | 首次拍照或录制完成时允许“添加照片”权限；系统设置中可单独调整相册权限。 |
| `xcodegen generate` 后工程文件有变更 | 仅在 `project.yml` 改动时运行它。若只是续期安装，不需要执行；提交前检查变更是否确实属于本次工作。 |

## 安装后的最小真机检查

开发签名和启动成功只说明包可以运行，不代表双摄功能已完全验收。每次重要版本至少检查：

1. 前、后摄预览都正常，切换布局、比例和后置镜头不会白屏。
2. 拍照后仍停留在取景界面，左下角缩略图出现“保存中”或“已保存”，照片最终在系统相册可见。
3. 开始视频录制后显示“录制中”和递增时长；停止后立即恢复照片取景，视频在后台保存。
4. 拒绝相册权限时，应用显示可操作的提示且不会崩溃；授权后可重试。

完整项目验收项见 [真机验收清单](真机验收.md)，每次构建／安装／信任的实际结果记录在 [执行日志](执行日志.md)。
