# 双摄相机使用说明

## 运行前准备

1. 使用 Xcode 打开 `DualCamera.xcodeproj`，选中项目导航栏中的 **DualCamera target**。
2. 在 **Signing & Capabilities** 选择自己的 Development Team，并设置唯一 Bundle Identifier。
3. 连接 iPhone 16 Pro，设备上信任开发者证书后点击 Run。
4. 首次运行允许相机权限；首次开始录制时再按需允许麦克风。第一次拍照或录制完成、应用开始自动保存时，系统才请求 add-only 的“添加照片”权限。

模拟器没有真实前后摄硬件。需要检查界面和合成流程时，在 Scheme 的 Run Arguments 加入 `-fakeCamera`；该模式的彩色占位画面不能替代真机验收。

## 拍照与布局

1. 顶部菜单选择可用的后置镜头。只显示系统当前允许与前摄并发的镜头。
2. 选择“画中画”“左右分屏”或“上下分屏”，以及 3:4、1:1、9:16 成片比例。
3. 画中画模式下，拖动前摄窗口可移动；松手会吸附到最近角落。双指在前摄窗口上捏合选择小／中／大尺寸；在后摄区域捏合则缩放后摄。
4. 点击后摄区域进行对焦／测光；前摄区域不接收该手势。网格、倒计时、镜像和保存选项位于设置菜单。
   缩放手势从开始时的倍率计算，录制中也允许对焦和缩放，但不会重建 Session。
5. 点击白色快门。倒计时结束后，应用在同一事务中并发请求两路照片，完成合成并自动开始后台保存。界面保持实时取景，不会自动跳转到全屏结果页。

“拍照质量”有两档：快速请求 `.speed`；均衡请求 `.balanced`。若某一路 MultiCam 输出只允许更低上限，应用会安全钳制。切换质量会在空闲时受控重建照片 Session，因此录制或拍照期间设置菜单禁用。

预览和成片共用同一布局参数；不过两路照片是近同步而不是严格同一曝光时刻。

## 照片保存、查看与分享

- 合成照片完成后会按设置自动保存：默认仅保存合成照片；可改为同时保存合成照片、前摄原图和后摄原图。两张单路照片优先直接写入相机 `fileDataRepresentation()`，不是 `UIImage → JPEG` 的二次编码；仅在系统没有返回文件数据时才记录降级并回退 JPEG。
- JPEG 处理和 PhotoKit 保存调度在独立队列执行；保存中、成功或失败会以左下角缩略图的进度、勾选或感叹号徽标表示，不会停止实时预览，也不会禁止继续拍摄。
- 点击左下角最近媒体缩略图才会打开照片查看页。“分享”仅打开系统分享面板，不会额外写入相册；关闭查看页只移除覆盖界面，底层 Session 在查看期间仍保持运行。
- 若“添加照片”权限被拒绝，应用会显示“去设置”入口；保存失败时，打开最近照片后可点击“重试保存”。
- 一张照片从入队到成功前都会占用一个待保存位；当前进程内最多保留 5 个照片任务。达到上限后，快门会提示先允许相册权限或点击“重试保存”，处理旧任务后才再拍照。

前摄方向规则：实时预览镜像由“前摄预览镜像”控制；合成照片由“前摄成片镜像”控制；单独保存的前摄相机文件保持相机自然方向。

## 视频

右侧红点开始录制，界面会依次显示“正在准备录制…”、带红点的“录制中”和“正在处理视频…”。录制时长使用等宽数字持续显示：不足一小时为 `MM:SS`，更长时为 `HH:MM:SS`。录制中点击中央按键停止。

当前视频为固定画中画、720×1280 H.264 + AAC。停止后应用会立即重建照片 Session 并恢复实时取景；视频写入器完成 finish 后自动在后台保存。如果写入期间又拍了照片，最近媒体仍按拍摄先后保留新照片，旧视频不会因较晚完成而覆盖它。保存不暂停取景；当前最近视频保存失败时，打开后可重试。

应用会保留当前最近视频的临时文件供查看。视频相册保存另行记录 saving/saved/failed 状态：新照片或视频替换它时，saving 文件延迟到成功后清理，saved 文件可立即清理，failed 文件则保留供恢复。这避免把“视频已生成”误当成“已保存到相册”而提前删除。

麦克风拒绝只会阻止视频并提供“去设置”，照片仍可继续使用。视频两路帧按最近可用前摄帧合成，属于近同步而非严格硬件逐帧同步。本版本没有新增视频布局、比例、滤镜、暂停继续、4K、ProRes 或后台录制。

## 保存失败与恢复

- 同一照片 UUID 或视频 URL 在 PhotoKit 真实回调前一直保持保存互斥；此时再点“重试保存”不会重复入队。应用不用本地超时提前释放互斥，避免底层 PhotoKit 仍在执行时重复写入。
- 当失败的媒体已被新缩略图替换，底部提示条会明确显示“一个较早照片／视频未能保存”：普通保存错误提供“重试保存”，相册权限被拒绝时提供“打开设置”。最近媒体仍可从缩略图的查看页单独重试。
- “重试保存”、“打开设置”或“重试相机”这类可操作提示不会被迟到的低优先级提示覆盖，也不会自动超时消失。恢复优先级依次为“重试相机”、“打开设置”、“重试保存”；用户点击按钮时，应用按该条提示的唯一 ID 消费，再执行设置跳转或重试，因此旧按钮不会误清后来出现的新提示。
- 失败照片的完整保存操作仅在当前进程内保留。失败视频会把标准化缓存路径写入恢复索引；即使 `CameraViewModel` 或 Controller 重建，只要 `.mov` 仍存在，应用在启动或回到 active 时仍会重试。不存在的路径会从索引移除。
- 开始新录像前，应用会把 failed 恢复路径和正在 saving 的视频 URL 合并去重，并统计实际存在文件的大小。达到 5 个或累计 1 GiB 时，不创建新 recorder，而是显示“重试保存”。这个容量闸门不会为腾出空间而静默删除任何待恢复视频。
- 相机界面正常退出并触发 `stop` 时，saved 的最近视频缓存会安全删除；saving 文件会等回调，成功后再清理；failed 文件和恢复索引保留供重试。若退出后视频才完成 `finishWriting`，它仍会脱离界面完成保存：成功后删除缓存，失败则记录路径供恢复。

## 隐私

相机画面、照片合成、视频与声音处理均在设备本地完成。应用仅使用 add-only 的“添加照片”权限，并在首次拍照或录制完成、自动保存开始时才发起请求。应用不上传、不远程分析拍摄内容。

## 生命周期与异常

- inactive（权限弹窗、控制中心等短暂状态）不会立即销毁 Session；真正进入后台才停止会话、取消尚未完成的照片工作并结束录制。回到 active 时按用户的运行意图恢复；打开最近照片／视频查看页不再是 Session 启动的否决条件。
- 系统中断时会取消当前事务并提示；中断结束后尝试恢复。
- `mediaServicesWereReset` 恢复路径会清空录制授权等待、Fake 录制、当次媒体序号和录制计时，并强制回到照片模式重建会话。若旧 writer 尚未进入 `finishWriting`，则可取消并回到 idle；若已进入不可取消的 `finishWriting`，则内部和界面保持 finishing，阻止新录像直到旧回调到达，不会先发布 idle 后再被旧结果覆盖。单次拍照失败、超时或取消不会把应用永久锁在“拍摄中”。
- 设置菜单中的“硬件诊断”会显示所选格式、帧率、`hardwareCost` 与 `systemPressureCost`。配置时会在 30fps／24fps 候选中有限降级，只有两项成本都不超过 1 才接受；运行期 serious 压力会尝试降至 24fps，critical／shutdown 会停止或阻止录制／会话。

## 常见问题

### 白屏、黑屏或不支持

确认使用的是实体 iPhone，且系统相机、视频通话、屏幕录制等没有占用摄像头。完全退出占用应用后重试。若仍不可用，请记录设置中的硬件诊断并按 [真机验收](真机验收.md) 提交结果。

### Xcode 无法安装到手机

确认在 **Signing & Capabilities** 已选择 Team、Bundle Identifier 唯一，并在“设置 → 通用 → VPN 与设备管理”信任开发者证书。

### 命令行提示缺少 iOS 平台组件

在 Xcode 的 **Settings → Components** 安装与当前 Xcode 匹配的 iOS 平台组件后，重新执行：

```sh
xcodebuild -project DualCamera.xcodeproj -scheme DualCamera \
  -sdk iphoneos -configuration Debug CODE_SIGNING_ALLOWED=NO build
```

### 在 Xcode 中找不到 target

左侧项目导航栏点击最上方蓝色 **DualCamera** 项目图标；中间编辑区左栏会分成 **PROJECT** 和 **TARGETS**。在 **TARGETS** 下点 **DualCamera**（不是顶部 Scheme 设备菜单），右侧选择 **Signing & Capabilities**。
